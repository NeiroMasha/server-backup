## По шагам
1. Заведи новый сервер: та же система (СИСТЕМА, ВЕРСИЯ), диск не меньше ... ГБ. Лучше у другого хостинга, если старый сам пострадал.
2. Поставь инструменты: `apt-get update && apt-get install -y --no-install-recommends restic zstd sqlite3 openssl`. Плюс то, на чём работали сервисы: Docker, СУБД, веб-сервер (список в описи, шаг 4).
3. Достань копию. Положи пароль в файл `/root/pw`, права 600, и выбери один источник.

   Из облака:
   ```bash
   export RESTIC_REPOSITORY="..." AWS_ACCESS_KEY_ID="..." AWS_SECRET_ACCESS_KEY="..." AWS_DEFAULT_REGION="..."
   export RESTIC_PASSWORD_FILE=/root/pw
   restic snapshots
   restic restore latest --target /restore
   ```
   С компьютера: скопируй архив на сервер (`scp`), затем:
   ```bash
   mkdir -p /restore
   openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -pass file:/root/pw -in emergency-ДАТА.tar.zst.enc | zstd -dq | tar -xf - -C /restore
   ```
4. Посмотри опись: `/restore/var/backups/server-backup/inventory.txt`. Там пакеты, службы, контейнеры, расписание, порты и файрвол.
5. Верни файлы и настройки на места из `/restore`, только то, что нужно этим сервисам. `/etc` целиком поверх новой системы не копируй: сломаешь сеть и вход.
6. Подними базы из `/restore/var/backups/server-backup/dumps`. Сначала роли, потом пустая база, потом данные.
   ```bash
   # SQLite: файл sqlite-имя.sqlite
   cp ФАЙЛ /путь/к/базе
   # PostgreSQL на сервере: файлы pgroles-local.sql и pg-local-база.dump
   # Ошибка «role already exists» на этом шаге не страшна.
   runuser -u postgres -- psql -q -f - < pgroles-local.sql
   runuser -u postgres -- createdb -O ВЛАДЕЛЕЦ БАЗА
   runuser -u postgres -- pg_restore -d БАЗА < pg-local-БАЗА.dump
   # PostgreSQL в Docker: файлы pgroles@контейнер.sql и pg@контейнер@база.dump
   # Контейнер с теми же настройками сам создаёт главного пользователя и базу, остальное добавит файл ролей.
   docker exec -i КОНТЕЙНЕР psql -q -U ПОЛЬЗОВАТЕЛЬ -d postgres < pgroles@КОНТЕЙНЕР.sql
   docker exec -i КОНТЕЙНЕР pg_restore -U ПОЛЬЗОВАТЕЛЬ -d БАЗА --clean --if-exists < pg@КОНТЕЙНЕР@БАЗА.dump
   # MySQL или MariaDB в Docker: файл mysql-контейнер-база.sql.gz
   zcat ФАЙЛ | docker exec -i КОНТЕЙНЕР sh -c 'MYSQL_PWD="${MARIADB_ROOT_PASSWORD:-$MYSQL_ROOT_PASSWORD}" exec "$(command -v mariadb || command -v mysql)" -uroot БАЗА'
   ```
7. Запусти сервисы в таком порядке: ...
8. Переведи домен на новый адрес у РЕГИСТРАТОР. Изменение расходится по сети от нескольких минут до суток.
9. Сертификаты: `certbot` выпустит новые, когда домен заработает.
10. Проверь: ЧТО ОТКРЫТЬ, ЧТО ДОЛЖНО ПРОИЗОЙТИ.
11. Снова настрой копии на новом сервере. Если старый сервер взломали, смени все пароли и ключи.
