# Куда класть копию в облаке

Главное правило: хранилище у другой компании, не у той, что держит сервер. Авария или взлом хостинга не должны задеть копию. Хостинг сервера видно по кабинету человека или по `whois АДРЕС_СЕРВЕРА`.

Выбирай сам и говори человеку, что делаем. Спрашивай только то, что он знает: где у него уже есть аккаунт и чем он может платить.

## По умолчанию: S3-хранилище

S3 это способ хранить файлы, который понимают почти все облака. Нужно завести бакет (папку в облаке) и ключ доступа. Заводит человек сам, в кабинете хранилища, агент объясняет, куда нажать.

Где искать: Yandex Object Storage, Selectel, VK Cloud, Timeweb Cloud, Backblaze B2, Cloudflare R2. Перед выбором проверь по сайту цены и способ оплаты: зарубежные могут не принять карту человека.

Цены здесь не указаны, они меняются. В плане назови человеку тариф с сайта выбранного хранилища и посчитай по размеру из осмотра.

Настройка у всех одна:
- бакет закрытый, без публичного доступа;
- ключ доступа только к этому бакету, не ко всему аккаунту;
- адрес хранилища, регион и формат ключа бери из документации этого хранилища, не по памяти.

Строки для `config`:

```
RESTIC_REPOSITORY="s3:https://АДРЕС_ХРАНИЛИЩА/ИМЯ_БАКЕТА/ИМЯ_СЕРВЕРА"
AWS_ACCESS_KEY_ID="..."
AWS_SECRET_ACCESS_KEY="..."
AWS_DEFAULT_REGION="регион хранилища"
```

Проверка: `restic init` создаёт хранилище в бакете. Если он ругается на адрес или подпись, чаще всего не тот регион или адрес.

## Если есть только Google Диск: через rclone

Подходит, когда платить за хранилище не хочется. Минусы: бесплатный объём быстро закончится, а скачивание большого архива идёт медленно.

```
RESTIC_REPOSITORY="rclone:gdrive:server-backups/ИМЯ_СЕРВЕРА"
```

Настройка:
1. На сервере `apt-get install -y rclone`, затем `rclone config`: новое подключение типа `drive`, имя `gdrive`.
2. На вопрос о правах выбери `drive.file`: rclone увидит только файлы, которые создал сам, и ничего больше на Диске человека.
3. Браузера на сервере нет, поэтому выбери ручной вход: человек выполняет `rclone authorize` на своём компьютере, входит в Google сам и вставляет ответ в свой терминал на сервере.
4. Файл `/root/.config/rclone/rclone.conf` содержит токен. Его не печатай.

`AWS_*` в этом случае оставь пустыми.

## Что не защищает

Ключ на сервере умеет и записывать копии, и удалять их: без этого не работает очистка старых версий. Значит, взломщик сервера с правами root может стереть и облачную копию. Страховка от этого: архив, который забирает компьютер (шаг 7 в SKILL.md). Сервер не знает, где он лежит, и зайти туда не может.

Запрет удаления на уровне ключа с этим инструментом работает плохо: restic сам снимает свои блокировки в хранилище, и ключ без права удаления ломает его работу. Настоящий вариант «дописывать, но не удалять» требует отдельного сервера с `rest-server --append-only` или `rclone serve restic --append-only`. Это отдельный проект. Предлагай его только тем, кому копии особенно дороги, и честно предупреждай, что в этом наборе он не проверялся.

## Что проверено

- Копия через rclone на Google Диск: работает на боевом сервере, хотя и не этими скриптами.
- S3: весь цикл прошёл на подставном S3-сервере (`rclone serve s3`). На настоящих облаках из списка не проверялся: при настройке смотри на результат `restic init` и первой копии.
